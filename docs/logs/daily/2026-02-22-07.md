 ## 下一步计划：推进 GAP-SUI-02（Break Value Expressions）

  ### 摘要

  当前 01/03/04/05/06/07/08 已完成，唯一未完成的核心 gap 是 docs/github-issues/sui-move-2024/02-break-value-expressions.md。
  下一步应集中完成 break <expr> 的 parser + type inference + 诊断回归，补齐 Move 2024 语义闭环。

  ### 目标与完成标准

  - 支持并稳定通过：
      - loop { break 1; }（有值 break）
      - label 场景中 break 'label <expr>
  - 类型汇合行为明确：
      - 同一 loop 多分支 break value 类型一致时可推断
      - 不一致时稳定报错（inspection/annotator）
  - 与旧 break; 语义兼容，不引入回归

  ### 实施范围（决策已定）

  1. Parser/PSI

  - 检查并修正 BreakExpr 语法，确保 break 后可选表达式在所有 block/loop/label 场景正确挂载 PSI。
  - 补 parser 快照用例（正向/反向各至少 1 组）。

  2. 类型推断

  - 在 TypeInferenceWalker/相关推断路径中为 loop 建立“break value 汇合类型”。
  - 规则：
      - 全部 break 无值 -> loop 结果 ()
      - 存在有值 break -> 以有值 break 集合做统一
      - 统一失败 -> 报类型不兼容错误
  - 保持 break; 与历史行为一致。

  3. 诊断与错误信息

  - 增加/校准 label + break value 场景报错：
      - 跳出目标非法
      - break value 类型冲突
  - 文案保持现有测试风格，避免不必要改词导致快照抖动。

  ### 可能影响的接口/类型（公共面）

  - 无外部 API 新增。
  - 仅内部语义行为变化：
      - BreakExpr PSI 解析结果
      - loop 表达式类型推断结果
      - 对应 annotator/inspection 报错集合

  ### 测试计划

  1. Parser

  - break_value.move / 快照：break 1;、break (1, true);、label break。
  - 反向：非法 break 位置与不完整表达式恢复。

  2. Types

  - ExpressionTypesTest 新增：
      - loop { break 1; } 推断 u64（或项目既定整数字面量默认类型）
      - 多分支一致类型通过
      - 多分支不一致类型报错

  3. Annotator/Inspection

  - 在 src/test/kotlin/org/sui/ide/annotator/errors/ 增加 label + break value 错误断言。
  - 运行定向 + 全量：
      - ./gradlew test --tests "*Break*"
      - ./gradlew test --tests "org.sui.lang.types.ExpressionTypesTest"
      - ./gradlew test --no-daemon

  ### 风险与兜底

  - 风险：break value 与现有 never/unit 处理冲突导致旧用例回归。
  - 兜底：先加失败用例再改推断；若冲突，优先保持 legacy 行为并在 Move 2024 路径分支处理。
